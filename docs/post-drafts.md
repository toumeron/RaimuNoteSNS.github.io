# 投稿先と下書きの保持

コミュニティの「ホームに固定」は、既存TLのタブにコミュニティを追加する操作。固定状態は既存のコミュニティ参加情報、並び順は従来のTLタブ設定を使用する。専用リンク列は置かない。通常の「最新」「フォロー中」等にはコミュニティ投稿を混ぜず、選択中のコミュニティ専用タブから取得する。

通常の投稿欄・PCオーバーレイ・モバイル全画面の公開範囲メニューには、参加状態が `active` のコミュニティを表示する。画像・動画・投票・予約にも `communityId` を渡す。コミュニティ由来の引用はそのコミュニティに固定し、送信時にも既存API・DBの権限確認を受ける。

文章と添付ファイルの下書きは端末内に保存する。新しいSupabaseテーブルや画像アップロードは使用しない。

- 本文は入力後に同期的にlocalStorageへ退避し、本文・切り抜き前後の画像Blob・投票画像・準備済み動画・投稿先・公開範囲・予約設定をIndexedDB `limenote-post-drafts` に保存する。
- アカウント、通常欄／オーバーレイ、コミュニティ、地図位置で保存先を区別する。オーバーレイのPC／モバイル表示は同じ下書きを使う。返信は表示形式・投稿ID・返信先ごとに分離する。
- 再表示・再読み込み時に新しいBlob URLを生成する。破棄済みの一時URLだけを保存して復元しようとしない。画像の復元完了前は送信と添付の変更を止め、復元待ちの間に入力した本文は上書きしない。
- 送信失敗時は保持する。成功後に限って送信済みの下書きを削除し、送信待ちの間に変更された入力は残す。削除がストレージ障害で失敗しても送信済みの下書きが復活しないよう削除印を残す。
- 投稿先変更や引用の取消しだけで本文・画像を消さない。アカウント切替時には前のアカウントの入力を画面から外し、本人の保存先だけを復元する。
- 保存先が利用できない場合は入力をメモリに残し、保存失敗を通知する。保存に失敗した入力がある場合は、再読み込み・終了時にブラウザーの離脱確認を使用する。端末のサイトデータ消去やストレージの強制削除を越えて保持する機能ではない。

検証は `src/lib/postDrafts.test.ts` と `src/components/feed/PostComposer.drafts.test.tsx`。実際の投稿欄3形式・返信欄6形式の閉じ直し、Blobからの復元、失敗・成功・送信中編集、アカウント切替、遅延復元、保存順序、保存障害を確認する。UI自動操作による実ブラウザー確認やGitHub Pagesへの公開は行っていない。
