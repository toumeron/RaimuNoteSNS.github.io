# アカウント凍結

既存の `public.profiles` の `Account_suspension`（boolean、既定値 false）で管理します。新規テーブルは作成しません。

Supabaseの管理画面で対象プロフィールの `Account_suspension` をONにすると凍結、OFFにすると解除されます。通常ユーザーによるフラグの設定・解除はDBが拒否します。

凍結中は閲覧を維持し、ポスト・返信・フォロー・いいね・DM送信・設定の保存・画像アップロード・AIチャット・検索等の操作を拒否します。既存の全37公開テーブルの書き込みガードは、直接RESTだけでなくSECURITY DEFINER RPCの内側でもログインユーザーを検証します。Storageは既存のポリシーに制限を追加し、Edge Functionsはサーバー側で状態を確認します。

投稿、返信、リポスト、レビュー、リスト等の公開コンテンツはRLSで非表示になります。投稿に依存するメディアやニュースも現在の凍結状態を検証します。凍結処理によるデータ削除はありません。解除後は既存データが再表示されます。凍結された投稿者のBot投稿だけを拒否し、Bot定期ジョブは停止しません。

凍結中は検索ページを検索処理の開始前に制限画面に置き換え、検索入力・サジェストを停止します。検索条件を付けたREST取得もウェブの通信層が拒否します。

ウェブUIにはホームの読み取り専用案内、プロフィールの凍結案内、テーマ色の拒否操作通知を追加しています。リストの既定ヘッダーはテーマ色の星に変更しました。操作拒否時・画面復帰時・再接続時に状態を再確認します。

2026-10-12に凍結用DBマイグレーションを本番へ適用・履歴へ記録し、関連Edge Functionsを配備しました。実際のアカウントの凍結・解除は行っていません。GitHub Pagesへの公開・mainへのpushは行っていません。

検証: ウェブ974件、Edge Functions15件、ローカルDBで直接書き込み・RPC・自己解除・Bot・Storageの拒否と解除後のデータ復元、型チェック、ビルド、390px/1280pxのブラウザー表示。通知に詳細ボタンや追加オーバーレイはありません。DBテストのデータはローカル専用です。
