# ボイスページの3Dモデル

標準キャラクター、読み込み形式、モデル制御とテストの構成をまとめる。

## 標準キャラクター

| 表示名 | 形式 | 機能 |
| --- | --- | --- |
| アリア | VRM 1.0 | 口パク、表情、まばたき、4種類のジェスチャー |
| リナ | VRM 0.x | 口パク、表情、まばたき、4種類のジェスチャー |
| ロボット | GLB / RobotExpressive | 待機アニメーション、対応表情、手振り・うなずき・ジャンプ系動作。口パク用モーフはなし |

モデルは `public/models/` に同梱し、選んだキャラクターに対応するモデルを表示する。

アリア・リナはLimeAI内の表示名です。元のモデル名・作者・利用設定はモデル内に保持しています。VRMサンプルはCC0ではありません。利用条件と出典は [LICENSES.md](../public/models/LICENSES.md) に記載しています。RobotExpressiveはCC0です。

## 読み込み対応

| 形式 | 対応内容 |
| --- | --- |
| VRM | VRM 0.x / 1.0。人型ボーン、表情、口パク、まばたき |
| GLB | モデル、対応モーフ、内蔵アニメーション |
| glTF | 自己完結ファイル、またはbin・テクスチャを含むZIP |
| FBX | モデル、対応モーフ、名前を判定できる待機・ジェスチャーのクリップ |
| OBJ | 単独モデル、またはOBJ・MTL・テクスチャを含むZIP |
| PMX / PMD | MMDボーン・対応モーフ・IK/grantランタイム更新 |
| ZIP | 上記形式と関連ファイルの展開。日本語パス、store / deflateに対応 |

アップロードは120MBまで。ZIPは800ファイル・展開後450MBまでです。モデルと参照ファイルはブラウザ内で扱います。単独ファイルが外部のbin・テクスチャ・MTLを参照する場合は、ZIPにまとめる案内を表示します。

ZIPにモデルが複数ある場合はVRM、GLB、glTF、FBX、OBJ、PMX、PMDの順に優先し、同一形式では浅いパスを優先します。意図したモデルを確実に選ぶにはモデル本体を1件だけ含めてください。

GLB/glTFにはDracoとMeshoptのデコーダーを設定しました。対応するデコーダー以外の圧縮形式はテスト対象外です。KTX2など別途トランスコーダーが必要な形式までの対応は保証しません。

## モデル制御

- ボイス画面の配置をページ全体のCSSが上書きし、画面や設定ボタンが正しく表示・操作できなくなる問題を修正。
- GLBなどのインポート時はラッパーで位置・大きさを調整し、モデルが持つ回転やスケールを維持。待機は認識できるIdle/Standing/Rest系クリップだけ再生し、先頭の歩行・死亡・攻撃クリップを勝手に再生しない。
- 連続切り替えでは古い取得を中止し、古い読み込み結果と進捗が最新の表示を上書きしない。途中で不要になったモデルも破棄。
- geometry、material、texture、skeleton、MMDランタイム、Blob URL、AnimationMixerを後始末。モデルごとの一時的な表情・ジェスチャー状態も初期化。
- MMDは会話用ポーズを適用する前にランタイムの前フレームの姿勢を戻し、更新を積み重ねない。表情名の数字サフィックス判定も修正。
- 対応ボーン・クリップがないジェスチャーはボタンを無効化。口パク対応の有無も設定に表示。
- モデル本来の姿勢を壊す全体回転による疑似ジェスチャーをやめ、汎用モデルは対応する内蔵クリップで動かす。
- 全身カメラにバンザイ・ジャンプの余白を追加。大きな頭のモデルのアップ表示では頭部サイズとモデルの奥行きを距離に反映。
- IndexedDBの保存はトランザクションの完了を待ち、接続も閉じる。アップロードIDにはUUIDを使い、空ファイルを拒否。

## テスト

実行手順は [アバターの回帰テスト](../tests/avatar/README.md)、テスト実装は [avatars.spec.ts](../tests/avatar/avatars.spec.ts) を参照してください。

標準モデルの選択・保存・復元、カメラ・照明・ジェスチャー、追加形式とZIP、破損ファイルからの復帰、連続切り替え時のリソース解放、モバイル幅の操作を検証します。認証と音声APIには模擬応答を使います。実機での描画、マイク認識、音声の聴感品質は別途確認が必要です。

口パク・表情・ジェスチャーはモデル内の対応モーフ・ボーン・クリップに依存します。FBX・OBJ・PMX・PMDのフィクスチャはパーサーと基本制御を検証するもので、任意の配布モデルや複雑なMMD物理演算への対応を保証しません。
